- For approved statuses (APROVADO, APROVADO_AUTOMATICAMENTE, APROVADO_PARCIALMENTE):
  - Require ADMINISTRADOR or CHEFE_DEPARTAMENTO (403 otherwise) — combines Phase 4 permission map + VOT-04 role requirement
  - Call reversal logic INLINE in same $transaction (not separate call to financeController.reverseProvision to keep atomic)
  - Reversal logic (adapted from financeController.reverseProvision lines 45-71):
    ```javascript
    await tx.$transaction(async (tx) => {
      // Conditional reversal (GA-VOT-05 pattern — Wave 4 will harden; use current pattern for now)
      const bal = await tx.fundBalance.findUnique({ where: { referenceYear: r.referenceYear } });
      if (!bal || bal.provisionedCents < r.approvedAmountCents) throw new Error('Provisionado insuficiente para estorno');
      await tx.fundBalance.update({
        where: { referenceYear: r.referenceYear },
        data: { provisionedCents: { decrement: r.approvedAmountCents }, availableCents: { increment: r.approvedAmountCents }, version: { increment: 1 } }
      });
      await tx.financialTransaction.create({
        data: {
          referenceYear: r.referenceYear,
          type: 'REVERSE',
          amountCents: r.approvedAmountCents,
          description: `Estorno por cancelamento: ${justification}`,
          metadata: { justification, decidedBy: req.user.role, action: 'cancellation_reversal' },
          requestId: r.id
        }
      });
      await tx.auditEvent.create({ ... action: 'request_cancelled', afterData: { status: 'CANCELADO', justification } ... });
      await tx.resourceRequest.update({ where: { id: r.id }, data: { status: 'CANCELADO' } });
    });
    ```
- For non-approved statuses: existing Phase 4 ownership check applies; simple status update to CANCELADO + audit (no financial reversal)

**financeController.reverseProvision:** Keep existing for mark-spent reversal; requestController.cancel uses inline version above for atomicity with audit.
