  <action>
Modify backend/src/routes/reports.routes.js per CONTEXT.md REP-02 and RESEARCH.md Pattern 2:

Add helper above toCSV:

```javascript
function sanitizeCSVCell(v) {
  const s = String(v ?? '');
  if (/^[=+\-@\t\r\n]/.test(s) || /^[＝＋－＠]/.test(s)) return `'${s}`;
  return s;
}
```

Then change toCSV's esc to call sanitize first:

```javascript
function toCSV(rows, cols) {
  const esc = (v) => {
    let s = sanitizeCSVCell(v);
    return `"${String(s).replace(/"/g, '""')}"`;
  };
  return [cols.join(','), ...rows.map((r) => cols.map((c) => esc(r[c])).join(','))].join('\n');
}
```

Key constraints:
- Single helper covers all CSV exports (requests, financial) — no per-route duplication
- Do NOT strip leading char — prefix with ' per OWASP prefix (preserves data)
- Order: sanitize raw String(v) first, THEN escape quotes — avoids breaking esc
- Export sanitizeCSVCell if needed for direct unit test (add to module.exports or keep internal and test via toCSV integration)
- Handle null/undefined via String(v ?? '')

After implementation, re-run REP-02 tests — they must now pass (green). Also test via CSV integration: create request with title "=CMD|' /C calc'!A0" and GET CSV, assert prefix.
