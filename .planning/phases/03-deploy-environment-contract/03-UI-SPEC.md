## Login-Flow Interaction Contract (normative for this phase)

This section is the prescriptive core of the contract. It locks observable login behavior
through the production topology without changing any visual element.

1. **Topology (locked, source: 03-CONTEXT.md D-09):** Cloudflare Tunnel is the official and only
   TLS termination. Path: Cloudflare edge (TLS) → cloudflared → server entry port → app port
   (plain HTTP internally). No Caddy alternative is documented or tested.
2. **Success path:** Admin opens the public `https://<host>` URL, submits valid `@utfpr.edu.br`
   credentials on the unchanged login card, and lands on `/` — `Secure` cookies are accepted by
   the browser because the edge presents HTTPS. Production sets `COOKIE_SECURE=true` explicitly
   (source: D-06); absent var follows `NODE_ENV` (production → true, source: D-05).
3. **No new client states:** `Login.vue` gains no loading skeleton, no new alert variant, no
   redirect screen, no topology-specific messaging. States remain exactly: idle → in-flight
   (`Entrando…`, disabled) → success (`router.push('/')`) / failure (error alert). Same-origin
   SPA+API is preserved behind the Tunnel, so no CORS split-host work exists (source: D-08).
4. **Unchanged by this phase (explicit non-goals):** `sameSite` stays `'lax'` (source: D-08);
   `trust proxy` / rate-limit configuration is Phase 8 SEC-03 work and Phase 3 configures
   nothing proxy-related (source: D-11); `./start-dev.sh` local dev flow is untouched
   (dev default `FRONTEND_URL=http://localhost:5173`, source: D-07).
5. **Dropped check:** The roadmap's `http://<LAN-IP>` plain-HTTP login verification is dropped —
   with `Secure=true`, plain-HTTP login cannot work by design (source: D-10). Verification is via
   the public `https://` URL only.
6. **Failure observability:** Cookie/topology misconfiguration must surface as the existing
   login error alert (server message or "Falha no login") — silent no-login with no feedback is
   a contract violation.

## Deploy-Contract Doc Shape (normative for this phase)

1. **Location (source: 03-CONTEXT.md D-12):** Dedicated deploy doc (README section or numbered
   `docs/` entry, planner's call) PLUS updated `backend/.env.example` (`COOKIE_SECURE`,
   `FRONTEND_URL=https://…` production notes). Inline compose comments alone are insufficient.
2. **Form (source: D-13):** Validatable checklist, not prose — three steps minimum:
   boot-refuses-insecure-secret → public-URL login works → `./start-dev.sh` dev intact —
   each step carrying its command + expected result.
3. **No visual/design requirement on the doc:** Markdown checklist; renderer-owned wrapping
   applies (per Phase 1 `docs/DESIGN.md` constraints — no raw HTML, tables ≤ 6 columns).
